# 论文一致性审查与修订计划

本轮依据上传PDF全文、冻结设计/执行计划与实际源文件逐项复核；Rust/C++语言差异不作为缺陷。

## 审查发现与修复顺序

1. **工作窃取后的执行顺序偏差（实质缺陷）**：论文§VI-B/C要求worker从本地deque最新端执行。旧scheduler.cpp把最早偷到的任务立即执行，后续偷到任务虽已进入本地队列，却不会被优先选择。修复为整批偷取按取得顺序入本地队列，再统一从本地最新端pop。保持随机非空victim、半队列快照、非阻塞deque、相同候选及验证逻辑。
2. **BFS消融的线程生命周期差异**：旧版每层创建/销毁线程，产生主LIFO没有的额外启动开销。计划未明确禁止此实现，但不利于论文调度消融的可比性。改为一次创建固定worker，主线程通过层首/层尾屏障推进完整BFS物化。失败时统一退出并join，线程创建失败也不能挂在屏障上。新增每worker thread_starts用于记录实际线程启动次数。
3. 测试先固定偷取顺序与worker启动指标，再验证三种调度的计数、取消/异常退出、独立真值差分及HB两模式；同步schema、README、实现记录与实测报告。
4. 根据独立审查发现补齐其它有证据的问题；没有原始数据/原硬件的数值实验明确列为未重跑，不能以缺失数据推导代码缺失，也不能声称已复现作者所有数值。

## 不改变的论文算法语义

Algorithm 2任务输入粒度、Algorithm 3 Card/交叠排序、Algorithm 4全部候选约束、Algorithm 5完整前缀profile、超边元组计数、精确去重、无标签静态移除标签比较均按原约定核对。模式仍固定奇数物理行忽略、偶数行实际边；query-id-base默认0。

## 独立审查补充：Algorithm 3复杂度

旧plan.cpp反复对已加入顶点并集和每条剩余边做完整集合扫描；二元星形k边查询中最坏达到Θ(k³)，未达到论文Algorithm 3的O(k²)选择阶段。修改为查询侧顶点关联表、顶点首次加入标记及每条边的overlap计数：每个查询关联最多更新一次，选择阶段保留k²评分比较。总开销为查询签名/关联准备加O(|Vq|+Σ|eq|+k²)。这是恢复论文顺序计算复杂度，不增加任何匹配剪枝或替代搜索路径。添加与独立集合版定义比对的顺序测试及2000条二元星形边测试。
